# Tiki Taka — исправленная учебная версия

Веб-приложение для просмотра, сравнения и подбора футболистов. Основная версия работает без Supabase, футбольных API и ИИ-подписок. Браузер обращается только к своему серверу Next.js. Интернет нужен для установки зависимостей; необязательные внешние изображения, шрифты и функции могут требовать подключения.

## Запуск на Mac / Windows / Linux

Установите Node.js 22 или 24. Откройте **эту папку** в VS Code, затем Terminal → New Terminal:

```sh
npm ci
npm run setup
npm run dev
```

Откройте http://localhost:3000 и перейдите на http://localhost:3000/admin. Перед первой регистрацией запустите `npm run setup` в терминале проекта и введите выданный код настройки; он позволяет владельцу создать первый аккаунт администратора. Используйте пароль от 12 символов. После входа можно создавать дополнительные аккаунты. Они хранятся в `data/accounts.json` в виде хешей паролей. Если порт 3000 занят, используйте адрес, показанный Next.js в терминале. Для остановки нажмите Ctrl+C.

Если меняете `.env.local`, перезапустите сервер. Свои старые ключи не требуются. Секреты из присланного архива намеренно не включены в исправленный архив.

## Языки сайта

В шапке сайта есть переключатель десяти языков: русский, английский, казахский, испанский, французский, немецкий, китайский, японский, корейский и португальский. Выбор сохраняется после перезагрузки. Переводы интерфейса хранятся в `assets/translations/*.json`. Код сайта — JavaScript/JSX (React и Next.js), поэтому пакет Flutter `easy_localization` не используется. Подробности и примеры: [docs/LOCALIZATION.md](docs/LOCALIZATION.md).

## Что исправлено

- Один каталог для главной, поиска, игроков, клубов, лиг, скаутинга и страниц новостей. Динамические страницы отражают добавления и удаления без пересборки.
- Добавление, изменение и удаление игроков сохраняются на диск. Пустой каталог не заменяется автоматически демонстрационным набором.
- Регистрация первого аккаунта администратора и создание дополнительных аккаунтов; пароли хранятся в виде хешей. Записи доступны только с подписанной HttpOnly-сессией. Проверяются источник запроса и входные данные, ограничиваются попытки входа.
- Отдельные пользовательские аккаунты доступны в разделе «Аккаунт». Они не имеют доступа к админке; очки и достижения разделяются между аккаунтами на этом устройстве.
- CSV: предпросмотр, проверка всех строк, атомарный импорт, экспорт. Неизвестный клуб, повтор ID или некорректное число отменяют весь пакет.
- Сравнение до 4 игроков одной позиции и сезона, статистика за 90 минут, график голевых действий.
- Скаутинг без ИИ: фильтры и объяснимый взвешенный рейтинг. Игроки с отсутствующими необходимыми показателями исключаются из расчёта.
- Профиль показывает сезон, источник, дату и статус данных. Отсутствующие показатели не выдаются за нули или оценочные минуты.
- Поиск через RapidAPI отделён от live-матчей. Внешние функции по умолчанию отключены и требуют входа администратора.
- Карьерные сценарии обозначены как иллюстративные ответы внешнего ИИ. Раздел площадок обозначен как демонстрация.
- Новый профиль начинает с 0 очков, без выданных заранее достижений.

## Проверка за 5 минут

1. Войдите в `/admin` с паролем из setup.
2. Скачайте «Пример CSV», загрузите его в той же странице и нажмите «Импортировать».
3. В `/players` выберите сезон `DEMO-2025/26`: появятся 3 синтетических игрока.
4. В `/compare` выберите Midfielder и этот сезон, отметьте 2–3 игрока.
5. В `/scout` выберите тот же сезон. Измените веса и посмотрите вклад каждого показателя.
6. В админке измените имя игрока. Проверьте каталог, поиск и страницу клуба.
7. Остановите и снова запустите сервер: изменения сохранятся.

## Источники и честность данных

Исходный `lib/data.js` содержит непроверенные примеры из присланного проекта. Они НЕ представлены как реальные текущие показатели. Из файла создаётся начальный каталог только при отсутствии `data/catalog.json`. Новости также являются демонстрационными текстами. Новые демонстрационные записи должны иметь `demo=true`. Для реальных данных заполните источник, сезон и дату; `demo=false` означает утверждение пользователя о происхождении, а не автоматическую проверку.

К каждому игроку относится одна запись одного сезона. Для другого сезона создавайте другой ID, например `pedri_2025_26`. `teamId` должен совпадать с ID существующего клуба. Статистику нужно брать за одну выбранную область соревнований: например только матчи Ла Лиги, без смешивания с кубками. Не сравнивайте рейтинги разных поставщиков как одну шкалу.

### CSV

UTF-8, запятая; текст с запятыми заключайте в двойные кавычки. Поддерживаются переносы строк внутри кавычек. Обязательные колонки: `id,name,position,teamId,season,source,updatedAt`. Дата — YYYY-MM-DD. Дополнительные колонки есть в `public/players-template.csv`; числа записываются с десятичной точкой. Пустое число = неизвестно. Ноль = известный ноль. `demo` может быть `true` или `false`, по умолчанию `true`. До 2000 строк и 1,5 МБ. Совпавший ID заменяет поля записи; экспортируйте резервную копию перед массовым обновлением.

### Расчёты

Показатель за 90 минут = показатель × 90 / фактические минуты. При неизвестном показателе или нулевых/неизвестных минутах возвращается отсутствие данных.

Скаутинг сравнивает только выбранную позицию и сезон, с фильтрами лиги, возраста и минут. По каждому активному показателю применяется `(значение − минимум)/(максимум − минимум)` внутри отфильтрованной полной выборки. Если все значения одинаковы, используется 0,5. Итог — сумма нормализованных значений с весами, делённая на сумму весов, умноженная на 100. Вес 0 отключает показатель. Это относительный пользовательский индекс, не вероятность успеха и не объективная оценка футболиста. Смена выборки меняет рейтинг. Для вратарей набор метрик ограничен: специализированного вратарского рейтинга пока нет.

## Хранение и перенос

Сервер сохраняет каталог в `data/catalog.json`. Записи последовательно обрабатываются одним процессом, файл заменяется атомарно. Файл создаётся при первом изменении. Для переноса после работы скопируйте всю папку `data`, а не только исходники. В админке есть скачивание JSON-копии и CSV игроков. Для восстановления JSON остановите сервер, убедитесь, что файл получен из вашей резервной копии, замените `data/catalog.json`, затем запустите сервер.

Эта конфигурация рассчитана на локальный запуск или один постоянно работающий Node.js-сервер с постоянным диском. Несколько серверных процессов и бессерверный хостинг с временной файловой системой не поддерживаются. Для такого размещения нужен отдельный адаптер PostgreSQL. На публичном HTTPS-сервере установите `COOKIE_SECURE=true`. Пароль администратора должен быть уникальным; его смена прекращает действие старых сессий.

## Необязательные внешние функции

Для Claude укажите `ENABLE_AI=true`, `ANTHROPIC_API_KEY`, при необходимости `ANTHROPIC_MODEL`. Для внешнего поиска — `ENABLE_FOOTBALL_SEARCH=true`, `RAPIDAPI_KEY`. Нужны собственные действующие ключи и подходящие тарифы. В этой работе запросы к платным сервисам не выполнялись. Вход администратора требуется для обоих маршрутов. Ни один из этих модулей не даёт трансляции матчей; live-счёт и live-статистика пока не реализованы.

## Проверки и сборка

```sh
npm test
npm run build
npm start
```

Интеграционная проверка: `npm run test:integration` после сборки. Скрипт сам запускает сервер на порту 3161, использует отдельный временный каталог и проверяет сохранение после перезапуска. Ваши данные не изменяются. При занятом порте задайте TEST_PORT.

## Для диплома

Возможная тема: «Разработка веб-системы анализа и подбора футболистов по статистическим показателям». Собственный вклад: единое хранение, проверка импорта, расчёты за 90 минут, многокритериальный подбор, интерфейс сравнения и контроль доступа. Требования кафедры и источники реальной статистики нужно согласовать отдельно.

Старые файлы Supabase оставлены как справочные; рабочие страницы их не используют. Автоматический перенос уже существующей удалённой базы не выполнялся.
