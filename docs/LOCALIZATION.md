# Языки интерфейса TikiTaka

Проект написан на **JavaScript / JSX**, использует **React 18 и Next.js 14 (Pages Router)**. Стили — CSS. `easy_localization` — пакет для Dart/Flutter, поэтому здесь используются маршрутизация Next.js и общий переводчик `useI18n`, без дополнительной библиотеки.

## Language codes и JSON

Переводы находятся в `assets/translations/<languageCode>.json`:

| Код | Язык |
| --- | --- |
| ru | Русский |
| en | Английский |
| kk | Казахский |
| es | Испанский |
| fr | Французский |
| de | Немецкий |
| zh | Китайский (упрощённое письмо) |
| ja | Японский |
| ko | Корейский |
| pt | Португальский |

Казахский имеет языковой код `kk` (код страны — `KZ`). Основной язык — `ru`. Next.js использует префиксы `/en`, `/kk`, `/es` и т. д. При первом посещении `/` Next.js учитывает язык браузера; после ручного выбора — cookie `NEXT_LOCALE`. Переключатель сохраняет текущую страницу, параметры поиска и положение прокрутки. При неизвестном коде используется русский язык.

Файлы импортируются при сборке. Переводы работают без API переводчика и внешних запросов. После изменения JSON на рабочем сервере нужна повторная сборка; в режиме `npm run dev` файлы обновляются автоматически. После изменения `next.config.js` перезапустите сервер разработки.

## Применение

```jsx
import { useI18n } from '../lib/i18n';

export default function SearchSummary({ count, query }) {
  const { t, languageCode, locale } = useI18n();
  return <p lang={languageCode}>{t('search.summary', {
    count: count.toLocaleString(locale),
    query,
  })}</p>;
}
```

`languageCode` — короткий код, например `kk`; `locale` — код для `Intl`, например `kk-KZ`. `t` возвращает обычный текст, который React экранирует. HTML в переводах не исполняется. Имена параметров между `{` и `}` должны совпадать во всех JSON.

Для нового сообщения добавьте один и тот же ключ во все десять файлов. Предпочитайте смысловые ключи (`search.summary`, `profile.nextLevel`) и целые предложения с параметрами. Исходные русские и английские подписи также служат ключами для совместимости с существующими компонентами и сообщениями сервера.

Переводятся подписи, кнопки, поля, меню, подсказки, статусы, ошибки, достижения, подтверждения, метаданные страницы. Числа и даты форматируются согласно выбранному языку. Ошибки API переводятся при отображении; технические значения запросов и коды полей сохраняются.

## Данные каталога

Имена игроков, клубов, пользователей, ID, источники и авторские тексты статей/описаний сохраняют исходное содержание. Для пользовательского контента разных языков нужны отдельные редакционные переводы в каталоге. CSV использует исходные имена колонок и значения позиций (`Midfielder` и т. д.). В формах переведённая подпись не меняет значение `<option value>`.

Включённый внешний ИИ получает указание отвечать на выбранном языке; уже полученные ответы автоматически не переводятся. Это не включает платный сервис и не меняет существующие требования доступа.

## Проверки

`npm test` проверяет модель данных, наличие одинаковых ключей и параметров во всех языках, перевод ошибок и форматирование чисел. `npm run build` создаёт страницы для всех десяти языков. `npm run test:integration` проверяет существующие API и защиту админки на отдельном временном каталоге.
